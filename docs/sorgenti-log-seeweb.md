## Capacità documentate e limiti

La [guida ufficiale Cloud Center](https://docs.seeweb.it/hosting/cloudserver/Cloud-Server/pannello/) descrive gestione dei prodotti e console; non certifica l'audit di login del tenant. La [REST API pubblicata](https://docs.seeweb.it/hosting/cloudserver/rest-api/API-Endpoints/) riguarda Cloud Server Shared CPU: la sua esistenza non dimostra un export dei login del Foundation Server o di Cloud Center. Non viene costruito un poller su un endpoint ipotizzato. Per Cloud Backup rimane valida la [pagina ufficiale del prodotto](https://www.seeweb.it/prodotti/cloud-backup), senza schema o API delle mail garantiti.

[Broadcom descrive i registri ESXi](https://knowledge.broadcom.com/external/article/306962/location-of-esxi-log-files.html): auth.log registra autenticazioni della Shell, mentre hostd.log riguarda gestione, task ed eventi. Il primo da solo non copre tutti i login web. L'[invio Syslog documentato](https://knowledge.broadcom.com/external/article/318939/configuring-syslog-on-esxi.html) è un canale candidato; prima della configurazione vanno verificati release, registri reali, certificati, limiti, raggiungibilità e ricezione sul collettore. Nessun comando di configurazione è eseguito sull'host.

Il firewall del tenant è ora identificato dalle schermate come OPNsense21.1.5. La [cronologia ufficiale della serie21.1](https://docs.opnsense.org/releases/CE_21.1.html) documenta fine vita e funzionalità successive: audit target in 21.1.6, TLS Syslog in 21.1.7. Non attribuirle alla release osservata. Il [dossier firewall](firewall-seeweb-opnsense.md) conserva configurazione, limiti e piano; il percorso di aggiornamento va concordato con Seeweb. Il precedente riferimento condizionale a pfSense non serve per questa appliance.
